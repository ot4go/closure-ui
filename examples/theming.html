closure-ui — Theming with CSS variables

The components style themselves; pages never need CSS to make them look right. When you want a different look, every component exposes CSS variables (listed per component in doc/closure-ui.md) that can be set on :root, on a wrapper, or on the element itself. This page demonstrates the technique — it is the only example page with a <style> block.

1. Shared design tokens

Default rendering (no CSS at all):

Inside a .corporate wrapper that redefines --primary, --border, --font… (focus a field to see the teal ring):

.corporate {
  --primary: #0f766e;
  --primary-light: #ccfbf1;
  --border: #99f6e4;
  --font: Georgia, serif;
  --text: #134e4a;
}

<div class="corporate">

</div>

3. <closure-tab-bar> palette

Default tabs, then a dark variant via --tab-bg, --tab-bg-hover, --tab-bg-active and the shared text/border tokens. The active panel's built-in frame follows --border/--tab-bg-active automatically; anything else is a plain closure-tab[active] rule:

4. One palette, whole shell: <closure-dashboard>

Homogeneous theming: every component falls back to the same canonical token values, so declaring the shared tokens once re-themes the dashboard shell — header, nav, selection, panels — and the components inside it (here a <closure-lazy-iframe>) in one stroke. The component-specific hooks (--dash-*, --lazy-iframe-*) cover the rest.

.slate-dash closure-dashboard {

  --dash-bg: #0f172a;
  --bg: #1e293b;             /* header + nav via their var(--bg) default */
  --border: #334155;
  --text: #e2e8f0;
  --text-muted: #94a3b8;
  --primary: #38bdf8;
  --dash-selected-text: #0f172a;
  --lazy-iframe-bg: #1e293b;
}
